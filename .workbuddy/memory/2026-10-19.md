## VESC 速度环+电流环 FOC 移植方案（指导，不改文件）

- 用户要求：把 VESC 的速度环+电流环移植到本工程，去掉多余变量/函数，只要必要参数；用户要自己手动移植，我先出方案。
- 方案要点（详见对话）：
  - 抄 VESC 的 4 个函数：observer_update / pll_run / svm / control_current 的 PI+解耦核心段；工具函数 utils_norm_angle_rad、fast_atan2。
  - 砍掉：HFI、encoder/hall、位置环、duty 模式、刹车、音频、弱磁、温度补偿。
  - 最小参数集：R、L、λ、极对数、observer_gain(=0.5/λ²)、电流环 kp=L*bw / ki=R*bw（bw≈1000 rad/s）、速度环 kp/ki、i_max、duty_max、i_scale、i_offset[3]、vbus_scale。
  - 关键硬件适配点：①TIMER_UPDATE_DUTY_MT 宏里 duty2/duty3 是交换的（CCR2=duty3），与采样顺序/Clarke 必须一致，否则电流环必炸——先确认或改回 CCR2=duty2；②电流换算 i=(raw-offset)*3.3/4095/(10*0.005)，GAIN=10、R=5mΩ、偏置中点≈2048；③观测器用的 v_alpha/v_beta 用"指令占空比×vbus"重构（板子无相电压采样）；④DRV8353H 是 3x PWM 模式，INLx 被忽略，软件无需改动；⑤电流环在 DMA1_Ch1 TC 中断里跑（20kHz），速度环放 1ms 任务。
  - 移植顺序：修 duty 宏 → foc_math 数学库自测 → 采样链路打印 → CAL 失调校准 → 开环拖转+观测器收敛 → id 闭环 → 观测器闭环 → 速度环。

## 下午：修 Keil 3 个编译错误 + 编码统一

- **错误定位方法（可复用）**：Keil 的构建日志在 `MDK-ARM/Foc/Foc.build_log.htm`，里面有完整 error 文本和行列号，比用户口述"3 个 error"精确得多。用户说"出了几个 error"时先读这个文件。
- 实际 3 个 error（来自 build_log）：
  1. `app_freertos.c(125): use of undeclared identifier 'MotorTaskHandle'`
  2. `app_freertos.c(125): use of undeclared identifier 'MotorTask_attributes'`（用户在 FunctionPrototypes 块里删了这两个声明，但 osThreadNew 调用还在）
  3. `mcpwm_foc.c(98): call to undeclared function 'ADC1_Current_Start'`（用户把 ADC1 初始化从 FOC_Init 挪进 app_adc.c 的 ADC1_Current_Start()，但没有原型）
- 修复：app_freertos.c 补回 MotorTask 声明（AboveNormal，1024B 栈）；app_adc.h 补 `ADC1_Current_Start(uint16_t*, uint32_t)` 原型；mcpwm_foc.c 加 `#include "app_adc.h"`。
- **顺带修了一个隐性 bug**：用户重构 ADC1_Current_Start() 时漏了 `LL_DMA_EnableIT_TC(DMA1, LL_DMA_CHANNEL_1)`——NVIC 虽然开了，但 DMA 通道级 TC 中断没使能，DMA1_Ch1 中断永远不进，FOC_ControlLoop 根本不会跑。已补上（并先 ClearFlag_TC1 防首帧误触发）。
- 行尾陷阱：mcpwm_foc.c / app_freertos.c / app_adc.c 是 CRLF，app_adc.h 是混合。用 Python 脚本改文件时先归一成 LF 再替换、最后还原主导行尾，否则锚点匹配不上（第一次跑就栽在这）。
- 另一个教训：脚本失败后重跑前要先确认上一步是否已落盘——这次 app_adc.h 的原型被重复插了 3 次（脚本 step1 成功、step2 assert 失败，重跑两次）。**脚本要幂等**，或失败后先检查再重跑。
