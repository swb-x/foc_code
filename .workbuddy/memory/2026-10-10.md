## FOC 项目：CubeMX 配置 vs 原理图审查

- 用户提供 Ctrl.pdf（MCU 板）+ Drv.pdf（驱动板）原理图，要求对照审查 STM32CubeMX 生成的初始化代码。
- 硬件：STM32G431CBT6 + DRV8353H（硬件版预驱）+ 6x CSD19532Q5B + 5mΩ 低侧三电阻采样；8MHz HSE（X3225）；TPS5430→5V→双 LDO 3V3/3V3A；SN65HVD232 CAN；I2C 外接编码器座（JP1）；USART1 调试座（JP3）。
- 审查结论：
  - 致命：TIM1 CH4 (CCR4)=0，TRGO=OC4REF 永不翻转 → ADC 触发链断裂，需设 CCR4≈4129（采样窗口居中于 CNT=ARR 峰值）。
  - FDCAN 位时序为默认值（3.54Mbps 非标准），AutoRetransmission=DISABLE，无过滤器 → CAN 实际不可用，需重配（给了 500K/1M 参数）。
  - TIM1 BreakState=ENABLE 但无刹车源，空配置；nFAULT(PA5) 只能走 EXTI 软件关断。
  - 原理图发现：DRV8353H 的 MODE(26) 与 GAIN(29) 短接共用 R35=47K→GND → 3x PWM 模式 + 10V/V 增益；3x 模式下 INLx 被忽略（TIM1 CHxN 无效），若要 6x PWM 需 MODE 直连 GND（但 GAIN 会变 5V/V，两引脚短接无法独立设置）。
  - 其余（时钟树 170MHz/PLL、ADC 42.5MHz、引脚分配、ENABLE/CAL/LED 默认低、VREF+ 外接 3V3A、TIM8 时基）均正确。
- 工具备注：本机 bash shim 环境 PATH 损坏（ls/mkdir 不可用），需用全路径调 Python；PDF 用 PyMuPDF 渲染+裁剪阅读。
- 后续：用户准备先测温度采集（ADC2_IN17/PA4，NTC 10K+3.3K 分压上拉 3V3A）。给了轮询读取 + Beta 公式(B=3950 占位，需按 NTC 实际 B 值) + printf 重定向到 USART1 的指导代码；25°C 时预期 raw≈1016、V≈0.82V。
- 调试：用户报"灯闪一下就不动，串口停在 adc_calibration done"。根因：自建任务时 `.stack_size = 128`——CMSIS-RTOS2 的 stack_size 单位是**字节**（CubeMX 默认是 128*4=512），128 字节跑 printf 直接栈溢出，LedCtrlTask 死在首个 printf（串口没有 "LedCtrlTask started" 即证据），堆/TCB 被踩导致全系统冻结。次要问题：FreeRTOS heap 3072B 太小（栈加大后要提到 8192）；app_adc.c 温度公式丢了 logf()；两任务无互斥并发 printf。用户风格：喜欢给指导和代码片段，不要直接改他文件。
